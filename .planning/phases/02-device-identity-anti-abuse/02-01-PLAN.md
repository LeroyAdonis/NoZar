**Edit 3 — Append two new table exports at the very end of the file (after `pushSubscriptions`):**

```typescript
// ─── Device Anti-Abuse Tables ─────────────────────────────────

export const deviceFingerprints = pgTable(
  "device_fingerprints",
  {
    id: serial("id").primaryKey(),
    fingerprintHash: text("fingerprint_hash").notNull(),
    userId: text("user_id")
      .notNull()
      .references(() => users.id, { onDelete: "cascade" }),
    firstSeenAt: timestamp("first_seen_at").notNull().defaultNow(),
    lastSeenAt: timestamp("last_seen_at").notNull().defaultNow(),
    trustLevel: text("trust_level").notNull().default("unknown"), // unknown | trusted | flagged
    registrationFingerprint: boolean("registration_fingerprint").notNull().default(false),
  },
  (t) => [
    index("device_fp_hash_idx").on(t.fingerprintHash),
    index("device_fp_user_idx").on(t.userId),
    unique("device_fp_user_hash_uq").on(t.userId, t.fingerprintHash),
  ],
);

// ─── Better Auth twoFactor Plugin Table ───────────────────────
// Matches the schema expected by better-auth/plugins twoFactor with
// drizzleAdapter({ usePlural: true }). Better Auth manages encryption
// of `secret` and `backupCodes` using BETTER_AUTH_SECRET internally.

export const twoFactors = pgTable("two_factors", {
  id: text("id").primaryKey(),
  secret: text("secret").notNull(),
  backupCodes: text("backup_codes").notNull(),
  userId: text("user_id")
    .notNull()
    .references(() => users.id, { onDelete: "cascade" }),
});
```

**Why this shape:**
- `device_fingerprints.unique("device_fp_user_hash_uq")` enables the `onConflictDoUpdate` upsert in the `/api/device-fingerprint` route (Wave 3).
- `twoFactors` column names use camelCase so the Drizzle adapter maps them to `two_factor_enabled`, `backup_codes` etc. in the DB — matching what Better Auth's plugin expects with `usePlural: true`.
- `twoFactorEnabled` on `users` is managed by Better Auth internally; adding it here lets Drizzle track the column in migrations.

  <action>
Run the following commands from the project root in order:

**Step 1 — Install runtime packages:**
```bash
npm install @fingerprintjs/fingerprintjs qrcode
```
This adds both to `dependencies` in package.json.

**Step 2 — Install type declarations for qrcode (qrcode ships no bundled types):**
```bash
npm install --save-dev @types/qrcode
```

**Step 3 — Generate Drizzle migration from the updated schema:**
```bash
npx drizzle-kit generate
```
This reads `drizzle.config.ts` and compares the current schema to the last
migration snapshot. It will produce a new `.sql` file in the `drizzle/` folder
containing `CREATE TABLE device_fingerprints`, `CREATE TABLE two_factors`, and
`ALTER TABLE users ADD COLUMN two_factor_enabled`.

**Step 4 — Apply the migration to the database:**
```bash
npx drizzle-kit migrate
```
This runs the pending SQL file(s) against the database specified in
`DATABASE_URL` (from `.env.local`).

**If drizzle-kit migrate fails with "relation already exists":**
The schema may already be partially applied (e.g. from a prior test run). In
that case, inspect `drizzle/meta/_journal.json` and mark the migration as
applied, or run `npx drizzle-kit push` to force-sync without a migration file.
  </action>
