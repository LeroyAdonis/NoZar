## Goal

Build the Profile tab (name/bio editing, avatar upload, TierBadge display, referral link sharing), the Billing screen (subscription tier + PayFast upgrade via WebBrowser deep link), the `billing/success` deep link handler, and the phone verification OTP screen.

## Requirements

- SC-03: Users can upgrade to Dealer/Premium via mobile billing screen; PayFast checkout opens via WebBrowser
- SC-04: Profile editing (name, bio, avatar upload) works on mobile
- SC-07: Phone verification OTP flow on mobile (Africa's Talking, matching web dashboard flow)

## Threat Model

| Boundary | Description |
|----------|-------------|
| apps/mobile billing.tsx → PayFast → nozar://billing/success | Deep link return must not grant tier upgrade without server-side signature validation |
| apps/mobile verify-phone.tsx → /api/otp-verify | OTP must be validated server-side; mobile only collects code |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-07-01 | Tampering | nozar://billing/success deep link | mitigate | The `billing/success.tsx` screen MUST NOT call any tRPC mutation to mark tier as upgraded — tier upgrade is applied ONLY by the existing `/api/payfast-webhook` server-side handler which validates HMAC signature before writing to DB |
| T-03-07-02 | Spoofing | /api/otp-verify bypass | mitigate | OTP is validated server-side (Africa's Talking token). The mobile screen only submits the 6-digit code — the server already enforces: correct code, within expiry window, bound to the requesting user |
| T-03-07-03 | Information Disclosure | Referral link sharing | accept | Referral links contain the user's referral code (not PII). User explicitly initiates sharing via expo-sharing |
| T-03-07-04 | Elevation of Privilege | Avatar upload MIME abuse | mitigate | `/api/upload` already validates MIME type server-side. expo-image-picker is configured with `mediaTypes: ImagePicker.MediaTypeOptions.Images` to further restrict on-device |

    ```typescript
    // apps/mobile/app/verify-phone.tsx
    import { useState } from "react";
    import {
      View, Text, TextInput, TouchableOpacity,
      Alert, ActivityIndicator, KeyboardAvoidingView, Platform
    } from "react-native";
    import { SafeAreaView } from "react-native-safe-area-context";
    import { router } from "expo-router";
    import { ArrowLeft } from "lucide-react-native";
    import { authClient } from "~/lib/auth";

    type Step = "enter-phone" | "enter-code" | "success";

    export default function VerifyPhoneScreen() {
      const [step, setStep] = useState<Step>("enter-phone");
      const [phone, setPhone] = useState("");
      const [code, setCode] = useState("");
      const [isLoading, setIsLoading] = useState(false);

      async function requestOtp() {
        const cleaned = phone.replace(/\s/g, "");
        if (!cleaned.startsWith("+")) {
          Alert.alert("Invalid number", "Enter your number with country code, e.g. +27831234567");
          return;
        }

        setIsLoading(true);
        try {
          const sessionData = await authClient.getSession();
          const token = (sessionData as { token?: string } | null)?.token;

          const res = await fetch(`${process.env.EXPO_PUBLIC_API_URL}/api/otp-request`, {
            method: "POST",
            headers: {
              "Content-Type": "application/json",
              Authorization: token ? `Bearer ${token}` : "",
            },
            body: JSON.stringify({ phone: cleaned }),
          });

          if (!res.ok) {
            const err = await res.json() as { error?: string };
            throw new Error(err.error ?? "OTP request failed");
          }

          setStep("enter-code");
        } catch (err) {
          Alert.alert("Failed to send code", String(err));
        } finally {
          setIsLoading(false);
        }
      }
    ```
